Preflight de CORS na API

Os Apaches das portas 8070 e 8071 usam o mesmo endpoint /receber.cgi. A comparação interativa envia o mesmo POST a cada um.

Por que o erro aparece depois do 307?

O fetch começa na mesma origem da página, na 8090. O 307 mantém o POST e seus cabeçalhos ao redirecionar a chamada para esta API. Como a porta muda, o navegador envia um OPTIONS antes de enviar o POST.

O navegador pede permissão para os dois cabeçalhos
Access-Control-Request-Headers: content-type,x-demo-token
Na porta 8071, um segundo set substitui a lista
Access-Control-Allow-Headers: X-Demo-Token
No cenário original da 8071, a API usa a lista inicial
Access-Control-Allow-Headers: Content-Type
A porta 8070 usa merge e acrescenta à lista existente
Access-Control-Allow-Headers: Content-Type, X-Demo-Token

Mesmo com 204 no OPTIONS, o navegador bloqueia o POST quando a lista deixa de fora um dos cabeçalhos que ele pediu. Uma chamada direta da 8090 com os mesmos cabeçalhos passa pela mesma verificação.

Uma única diretiva set também funciona se receber a lista completa.

Header always set Access-Control-Allow-Headers "Content-Type, X-Demo-Token"
